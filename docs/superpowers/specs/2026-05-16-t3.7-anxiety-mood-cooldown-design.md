# T3.7 — Anxiety slider + mood check-in + cool-down timer

**Status:** Approved 2026-05-16. Branch: `v1.1/build-sprint`.
**Constraint:** All three are optional, local-only, and feed analytics. Nothing blocks trading.

## Data model

Mirror every change across `schema.sql` (DDL / fresh install + test harness),
`src/lib/db/schema.ts` (Drizzle), and a new `applyMigrationNNN()` in
`src/lib/db/client.ts` (existing-DB upgrade). This is the parity rule that the
recurring schema-drift bug exists to enforce.

1. **Anxiety** — add `anxiety_level INTEGER` to `trades` (nullable, 0–10).
   Sits next to `pre_trade_emotion`. NULL = not recorded.
2. **Mood check-in** — new table `mood_checkins`:
   - `id TEXT PRIMARY KEY`
   - `account_id TEXT REFERENCES accounts(id)` (nullable — global check-ins allowed)
   - `mood_score INTEGER NOT NULL` (1–5)
   - `note TEXT`
   - `checked_in_at_utc TEXT NOT NULL`
   - `created_at_utc TEXT NOT NULL`
   - Index on `(account_id, checked_in_at_utc)`.
3. **Cool-down config** — `settings` rows, no schema change:
   - `cooldown_enabled` (`'true'`/`'false'`, default `'false'`)
   - `cooldown_minutes` (default `'15'`)

## Behaviour

- **Anxiety slider**: optional 0–10 slider on `<TradeForm>` next to emotion.
  Empty → `anxietyLevel: null`. Zod: `z.number().int().min(0).max(10).nullable().optional()`.
- **Mood check-in**: standalone widget; writes one `mood_checkins` row per
  submit. Independent of `reviews`. IPC: `mood:checkin`, `mood:list`.
- **Cool-down timer**: advisory + dismissible. When `cooldown_enabled` and the
  account's most recent *closed* trade is a loss whose `closedAtUtc` is within
  `cooldown_minutes` of now, `<TradeForm>` shows a dismissible countdown
  banner. Never disables submit. Loss detection reuses the existing
  `net_pnl < 0` convention used by T3.5.

## Analytics

Extend `src/lib/pnl.ts` aggregate (same pattern as T3.1/T3.5):
- `anxietyOutcomeCorrelation` — Pearson r between `anxiety_level` and
  `r_multiple` over trades where both are non-null; `null` if < 3 points.
- `moodTrend` — ordered `{ at, score }` series from `mood_checkins`.
Surface in a dashboard widget. Pure functions, fully unit-tested (Rule 3/4).

## Units & interfaces

- `src/lib/pnl.ts`: `anxietyOutcomeCorrelation(trades)` + extend aggregate. Pure.
- `electron/ipc/mood.ts`: `mood:checkin`, `mood:list`. Drizzle only (Rule 6).
  No audit_log row: a mood check-in is wellness data, not a trade mutation, so
  Rule 14 does not apply. Avoiding it also avoids an audit_log CHECK rebuild
  migration. (Anxiety is a `trades` field — its audit row comes free from the
  normal trade-create/update path.)
- `src/components/.../AnxietySlider.tsx`, `MoodCheckin.tsx`, `CooldownBanner.tsx`.
- Cool-down is a pure helper `computeCooldown(lastClosedLoss, minutes, now)` →
  `{ active, secondsRemaining }`, unit-tested, UI just renders it.

## Out of scope (YAGNI)

No reminders/notifications for mood. No cooldown for non-loss trades. No
historical backfill of anxiety. No per-setup cooldown. Audit-log entity enum
extension is additive only.
